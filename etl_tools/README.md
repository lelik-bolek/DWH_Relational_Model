Данный раздел содержит SQL-инструменты для предварительных трансформаций данных, применяемых до этапов логического моделирования и нормализации (1НФ → 3НФ).

Назначение этих инструментов — привести исходные данные в структурированное, согласованное и анализируемое состояние, пригодное для:

* устранения нарушений НФ;
* формирования staging-слоя;
* дальнейшего применения правил нормализации и историчности (SCD).

Инструменты в этом разделе:

* не являются частью целевой реляционной модели;
* не описывают бизнес-сущности;
* решают технические задачи подготовки данных.

Раздел спроектирован как расширяемый: со временем здесь могут появляться инструменты для других типов трансформаций (очистка, дедупликация, парсинг, приведение типов, валидации и т.д.).

---

**Инструмент: explode_multivalue_columns.sql**

Рассматриваемый кейс:
исходная таблица содержит мультизначные атрибуты, сохранённые в строках с разделителями (например, списки курсов, преподавателей, оценок), где логически связанные значения должны быть восстановлены в построчное представление.

Подход основан на одновременном раскрытии массивов с использованием `unnest` и `WITH ORDINALITY` для сохранения позиционного соответствия элементов.

Особенности:

* компактный и декларативный SQL;
* корректно сохраняет связи между значениями при согласованных данных.

Ограничения:

* требует равной длины массивов;
* чувствителен к рассинхронизации исходных данных.

Рекомендуется использовать, когда структура данных стабильна и контролируема.

---

**Инструмент: explode_with_generate_series.sql**

Рассматриваемый кейс:
аналогичная задача восстановления строк из мультизначных атрибутов, но с явным контролем индексов элементов массива.

Подход основан на генерации последовательности индексов через `generate_series` и обращении к элементам массива по позиции.

Особенности:

* более явная и пошаговая логика;
* проще расширять и отлаживать;
* легче добавлять проверки и обработку аномалий.

Ограничения:

* более многословный SQL;
* требует аккуратной работы с длинами массивов.

Рекомендуется использовать в обучающих сценариях и при работе с потенциально «грязными» данными.

---

**Архитектурная роль**

Результаты выполнения данных инструментов используются как промежуточный слой между исходными данными и нормализованной моделью.
Они формируют техническую основу для дальнейших шагов моделирования, не смешивая трансформации данных с архитектурой хранения.

Такое разделение позволяет:

* сохранить чистоту логической модели;
* чётко отделить подготовку данных от их моделирования;
* масштабировать проект без архитектурного долга.
