В 2НФ:
- Таблица должна быть в 1НФ + все неключевые атрибуты зависят от ВСЕГО первичного ключа.
	Вынести атрибуты, зависящие только от части составного ключа, в отдельные таблицы.
	PK(student_email, course_name, order_date)
	
В 3НФ + SCD Type 2:

	- 3НФ. Таблица должна быть в 2НФ + не должно быть транзитивных зависимостей.
	
	- Историчность:
	В исходной модели 3НФ справочники хранят только актуальное состояние объектов. При изменении атрибутов данные прошлого искажаются, так как факты начинают ссылаться на обновлённые значения.
	Для системы продаж курсов это приводит к:
		потере информации о состоянии данных на момент покупки;
		искажению аналитики за прошлые периоды;
		невозможности корректного аудита изменений.
	
	- Подход SCD Type 2

	Для хранения истории изменений справочников выбран подход Медленно Меняющихся Измерений, при котором:
		каждая версия объекта хранится отдельной строкой;
		явно фиксируется период её действия;
		предыдущие версии не удаляются.

	Этот подход позволяет:
		анализировать данные «как было на тот момент»;
		связать факт с конкретной версией справочника;
		сохранить простоту SQL и прозрачность модели.
